# 2026-10-03 小车自带热点与 GL 外接 WLAN 评估

本文保留先前 5 GHz 自带热点与 2.4 GHz GL 的短测结果及当时建议。当前采用用户首选的 GL；后续新增了同为 2.4 GHz／频道 6 的对照，详见 [链路隔离报告](PATH_ISOLATION_2026-10-03.md)。本记录的短测范围不能作为 GL 根因已确认或已修复的依据。

建议在当前摆放位置优先使用小车自带的 5 GHz 热点作为视频和控制连接，GL-MT300N-V2 保留为备用或独立网络管理设备。这个结论来自实际手机视频和网络采样，而非“自带/外接”或标称带宽的比较。远距离、隔墙覆盖尚未实测；不能推广为所有外接路由器都不如自带网卡。

## 测试条件

- 同一部 BRA-AL00 手机、同一 App 进程，使用相同短段 MJPEG：`fps=30&frames=12`。预览 JPEG 实测为 640×360，没有在两条链路之间降低帧率或画质。
- 自带热点：`WSZN-2BFE2915`，5180 MHz/channel 36，手机 RSSI 约 −41～−44 dBm，协商速率 65～72 Mbps，服务地址 `http://192.168.149.1:8080`。
- 外接热点：`GL-MT300N-V2-c37`，2437 MHz/channel 6，手机 RSSI 约 −27～−31 dBm，协商速率约 130 Mbps，车端通过 100 Mbps eth0 接入，地址 `http://192.168.8.204:8080`。
- 两轮有效视频窗口均为 381.701 秒（约 6 分 22 秒）。GL 另外观察至约 11 分 18 秒。手机及电脑接入所测热点，车端另一网络接口保持原配置。
- 两轮车端 `camera_preview.py`、`phone_mode.py` SHA256 一致；但服务在两轮之间发生一次自动重启，因此不能宣称使用同一服务进程。
- 没有发送车辆运动指令；多次状态读取均为 moving=false。没有验证运动中掉线、隔墙或行驶范围。

## 测量结果

| 指标 | 自带 5 GHz 热点 | GL 外接 2.4 GHz 热点 |
| --- | ---: | ---: |
| 同等时长视频 FPS 中位数 | 29.8 | 29.7 |
| 同等时长最大新画面间隔 | 242 ms | 1985 ms |
| 出现超过 1 秒帧间隔的统计区间 | 0 | 10 |
| 同等时长短段请求失败/到期计数 | 1 | 54 |
| 同等时长看门狗关闭 | 0 | 0 |
| 视频负载下手机 → 小车 ICMP | 1500/1500，0% 丢包 | 1442/1500，3.87% 丢包 |
| 视频负载下手机 → 小车最大 RTT | 170 ms | 1769 ms |
| 手机 → 路由器 ICMP（GL 视频负载下） | 不经过 GL | 1462/1500，2.53% 丢包，最大 1778 ms |

视频 FPS 是约每秒解码上报的统计值，不能把目标 30 FPS 写成每一个瞬间都达到 30 FPS。自带热点这轮接近 30 FPS，仍有短时波动；GL 的 FPS 中位数也接近 30，但长停顿使部分上报区间降至约 0.5～6 FPS。超过 1 秒的统计区间数量不是精确独立停顿次数。

GL 延长观察在 11:05:08.800 触发一次真实视频看门狗：`dataAge=2322 ms`、`decoding=false`、`tickGap=502 ms`，11:05:10.509 重新启动预览。完整 GL 观察中有 18 个统计区间出现超过 1 秒的新画面间隔。视频恢复逻辑保留了连接，但没有消除传输停顿。

小车 eth0 → GL 路由器的独立采样为 60/60、零丢包，RTT 约 0.42～0.57 ms。结合手机直接 ping 路由器也丢包，证据主要指向无线接入/转发段；尚不能区分无线干扰、路由器驱动/固件或终端交互，更不能断言 GL 硬件已损坏。ICMP 丢包也不能直接等同于视频 TCP 丢包率。

## 独立发现与统计排除

首次建立 GL 视频连接时，`astra-phone.service` 从 PID 6658 自动重启为 PID 15061，NRestarts=1。项目日志保存了异常：

```text
main.py:229 -> camera.check_fresh()
camera_broadcaster.py:153
RuntimeError: Camera unavailable or frame expired; refusing stale image
```

首次未正常播放的连接尝试已剔除，正式 GL 视频窗口从 10:57:12.152 开始。这个相机帧过期故障需要独立排查，换 WLAN 不能保证消除它。后续服务状态曾确认 camera=live、moving=false；结束时电脑路径 SSH 超时，不能据此宣称整车不可访问，也不能保证结束时重启计数仍未变化。

自带窗口止于 10:45:05.751。随后主动进入 WLAN 设置以切换测试网络，10:45:08.131 的视频超时不纳入此前正常播放段。切换期间曾发现电脑和手机连接到家庭 WLAN；车端 NetworkManager 热点仍 active，原因尚未确定，不能宣称后台或自动换网行为已经稳定。

## 使用建议与结束状态

当前建议手机连接 `WSZN-2BFE2915`，App 地址使用 `http://192.168.149.1:8080`，保留 30 FPS 视频和现有安全保护。GL 可以继续保留用于备用连接、接入其他设备和管理独立局域网；此次数据没有显示它在当前视频场景中的优势。

GL-MT300N-V2 官方规格为仅 2.4 GHz、标称 300 Mbps 无线和 10/100 Mbps 网口；这些标称速率不代表实时视频延迟或稳定性。[GL 官方规格](https://www.gl-inet.com/en-us/products/gl-mt300n-v2)

如果主要使用环境是隔墙或较远距离，需要在实际位置补测丢包、长停顿及覆盖，再决定主连接。本次强信号位置的结果不能替代覆盖测试。

结束时手机已接入自带热点，但在最终重建 App 连接过程中锁屏。系统返回 10106102，明确禁止锁屏时启动 App；最终前台播放确认尚未完成。App 在尝试重建连接时已关闭，需解锁后重新打开；电脑最后确认仍连接 GL WLAN。现有车端服务已为测试启动，未调整开机自启、热点或路由器配置；本次未修改 App/车端业务代码或安全看门狗。
